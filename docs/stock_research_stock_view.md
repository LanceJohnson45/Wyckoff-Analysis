# 固定报告内的个股事实

现有Agent的「策略研究」视图内，报告下方提供「个股事实与快照行情」。可点选报告涉及公司，或输入本次完整股票池内的大写代码。每次查询固定run_id与report_id；切换报告修订会切换个股上下文，不把另一修订的缓存当作当前结果。

图表复用既有K线组件的priceOnly模式，只使用返回的同口径快照OHLCV，不添加自动派生的均线、结构指标、启发式事件标记或支撑压力。价格/成交量图不证明盘中触发或成交。Martin的短/中/长周期EMA、ATR/ADR、相对SPY收益差及其他因子来自原产物；周期和算法不从图表重新推断。全部因子、条件、支撑与锚点的标量引用可展开，数据缺失保持null，不补零。

量化池、有效计算和正式初选分别表达。行业/已确认主题显示当时成员、覆盖及可用得分，成员或覆盖不足时继续保留原因。「带此股票证据继续讨论」将固定股票事实及该报告当时的初选/互评带入既有对话，历史只展开最近20根并保留总数。尚未把专用研究工具注册到该Agent模型循环。

## 固定修订查询

HTTP股票观察新增可选report_id：

```text
GET /v1/stocks/{symbol}/observations?run_id={RUN_ID}&report_id={REPORT_ID}&limit=320
```

报告必须与run和workspace匹配，否则404。指定后，初选与互评只取该报告当时保存的视图；未指定时读取当前run已提交意见。两者的行情、因子、参数摘要仍来自相同冻结快照，历史上限320根，响应回显report_id（run视图为null）。

只读CLI和MCP同步支持该标识：

```bash
.venv/bin/python -m stock_research.query_cli stock --symbol ACGL --run-id "$RUN_ID" --report-id "$REPORT_ID" --limit 60
```

MCP的stock_research_stock增加可选report_id，追问某份固定报告时应一并提供，避免把后来才产生的观点写回旧报告。

## 已验证范围

原生PG测试证明，运行早期修订的股票查询不包含后来提交的初选/互评，当前run查询仍能看到它们；HTTP覆盖跨run报告拒绝。前端校验run/report/snapshot/截止日/公司身份，拒绝未来或重复日线、策略缺失；图表消费的纯行情覆盖数据确认为空，默认图表覆盖行为保留。

真实前端请求客户端经Node代理读回完整报告绑定的320根日线与两策略事实，独立CLI与MCP指定相同report_id读回一致。全量Python5962通过，聚焦171通过；完整Web gate通过，Web379、API221（默认外部Upstash两项跳过）、TypeScript与两项构建通过，bundle未含两种研究身份。

实际浏览器仍等待现有账号登录，画布绘制、切股、表单、展开和讨论操作尚未验收。已确认锚点的图上叠加、分组整池查询、参数/主题/自选维护与Personal部署仍需接续；无收益、交易许可、远端CI、wiki同步或部署验收声明。
