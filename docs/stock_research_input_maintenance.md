# 主题确认与人工自选

既有Agent「分组与自选维护」管理下一次研究输入，当前报告继续使用原冻结版本。主题先保存建议，复核完整成员、加入/移除差异、来源与理由后，显式确认发布；成员是该主题完整定义，空成员表示清空。建议保存不影响量化，旧修订冲突须读取当前状态并重新提议，不自动换修订重发。

自选按代码先读取当前最高修订，再显式加入/更新或移除manual关系。移除不删除标普/纳指成分。行业只补缺，已有有效行业不通过自选覆盖；新代码缺行情/分类时继续保留并按既有质量门槛处理，不伪造因子或放宽覆盖。来源、理由、确认时间、日期和完整定义均保存在追加记录中。

## 日期与冻结消费

生效日不能早于确认时的纽约日历日期，可以指定未来日期。创建研究时，按行情as_of从同一条MVCC查询取得各目标已生效最高修订；未来发布与pending建议不进入更早截止日。该规则不将当前人工资料冒充严格PIT历史成分/分类，原有数据限制仍保留。基线或成员资格变化须重新复核；已确认主题后来缺分类的活跃成员保留在主题分母中，显示缺资料而不补行业。

API新建与CLI默认run在快照前解析主题、自选和基线，先按摘要物化版本文件，随后快照和量化只读取这些文件；来源与实际快照摘要必须一致。新主题进入原production group_facts与Martin计算，不复制分组算法。输入版本摘要参与幂等键，来源标签只描述首次冻结，同版API/CLI不重复选股。历史来源不被后来入口补写。

显式run --snapshot-file保持原文件版本，不套用当前发布。单独snapshot --offline仍只读operator配置的版本文件，不暗中连接PG；默认run的内部离线快照读取的是已解析物化文件。旧报告及旧快照不会重新解释；旧运行缺来源字段时只展示原快照摘要，不补造发布历史。

## API与持久化

| 入口 | 行为 |
|---|---|
| GET、POST /v1/theme-proposals | 私有建议SQL分页/创建201，POST携16～128字符Idempotency-Key |
| GET /v1/theme-proposals/{id} | 建议、基准/当前修订、原完整成员及真实确认关联 |
| POST /v1/theme-proposals/{id}/confirm | expected_revision与effective_date；同确认重放原发布，异参409 |
| GET /v1/input-publications | kind=theme/manual，可按target过滤的追加历史 |
| GET、POST /v1/universe-overrides | 私有自选历史SQL分页/创建201，POST带幂等键、预期修订及日期 |
| GET /v1/universe-overrides/{symbol} | 含未来发布的最高修订，用于CAS；不是某历史截止日配置 |
| GET /v1/research-runs/{id}/inputs | 原运行的冻结版本、摘要与发布关联 |

分页page=1～1000000、page_size=1～20，按创建时间/UUID稳定排序。发布按workspace、kind、目标串行CAS，主题还绑定提议基准及operator原始文件摘要；同键异参409。读取校验payload、请求摘要、索引及主题原提议关联。终态发布不覆盖，来源损坏503，不退回默认文件冒充成功。

显式init-schema增加theme_proposals和input_publications，研究schema现有26表。API启动只检查，不自动迁移。人工维护历史、建议与冻结来源仅operator可读写，共享API_READ_TOKEN的相关GET也403。问答八工具不增加确认或维护入口，模型没有operator身份。正式多用户账号托管仍属于部署验收。

Node开发代理保持loopback/同源/固定路由；建议创建与自选发布正文上限64KiB，问答创建48KiB，其他写入8KiB。凭据不进入VITE、浏览器持久化或bundle。网络结果未知时锁住新操作，使用原请求/幂等键核对；原发布不会变成自动覆盖。
