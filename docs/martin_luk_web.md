# Martin 辅助扫描网页版

## 本地行情链路改造验收

目标：Actions维护云端PostgreSQL，显式同步增量到本机SQLite，网页扫描只读本地库。

验收项：①真实SQLite写入后重开读取；②重复同步幂等、历史修订更新；③失败不推进水位、重跑恢复；④PostgreSQL真实只读分页抽样同步；⑤网页断网读取、缺库提示、同步后立即读到新数据；⑥两市场Actions补齐基准写库步骤。云端PG测试不以SQLite替代；SQLite测试仅验证实际本地存储。此次不修改云端表结构、不删除现有行情、不触发或停用线上Actions。

本功能是单页日线研究工作台。复用现有Streamlit与云端日线表，本地用SQLite，不增加独立服务或云端表。PDP豁免：单页实现。

## 打开方式

在仓库目录使用已有虚拟环境。首次先同步，再启动独立入口：

```bash
.venv/bin/python scripts/sync_local_market.py --market all
.venv/bin/python -m streamlit run martin_luk_app.py --server.address 127.0.0.1
```

浏览器打开终端打印的地址。独立入口不读取账户、持仓或用户设置，不需要LLM API Key。扫描、基准读取和图表全部读本机SQLite，断网仍可分析已同步的股票。仅点击“从云端同步到本机”或执行同步命令才连接PostgreSQL；同步过程也不会调用行情接口。

主应用 `streamlit_app.py` 左侧导航也有“Martin 辅助扫描”；该入口继续使用现有登录校验。独立入口仅用于本地运行，未提供对外服务的认证、限流和访问控制，也未部署到线上。

## 使用流程

1. 选择 A 股或美股，输入自选股代码，每批最多20只。初始代码仅展示格式，不是推荐。
2. 选择本地行情库或上传日线CSV；首次可在“本地行情库与云端同步”选择当前自选股或全市场，显式同步。
3. 选择截止日，可读取本地沪深300／SPY，计算日期严格对齐的20日超额收益。
4. 点击“开始扫描”，分别查看成功结果和数据问题。
5. 按形态过滤，打开单股观察卡，检查日K与均线、成交量、证据、待确认动作和失效参考。A股红涨绿跌，美股绿涨红跌。
6. 可导出当前过滤结果 CSV。切换输入条件后，原结果隐藏，需重新扫描。

输入、上传及扫描结果保存在当前Streamlit会话；上传文件不写盘、不放共享缓存。本地日线持久保存于SQLite，网页不使用旧的15分钟网络行情缓存。不同股票实际数据日期可能不同，结果逐股展示日期；日期早于请求截止日时提示历史状态，超过7个自然日另提示陈旧风险。成功同步改变当前市场覆盖或水位后，旧扫描结果隐藏；重新扫描始终读取本地最新数据。大库覆盖统计按本地文件版本缓存，切换观察卡不重复统计全表。

## 云端到本机的增量同步

使用现有`.env`中的`PG_ENABLED=1`和`PG_*`连接配置。连接强制只读、可重复读；本机没有云端INSERT/UPDATE代码。SQLite默认文件为`data/local_market.sqlite3`（已加入gitignore），可用`LOCAL_MARKET_DB_PATH`指定其他本机文件。不把数据库密码存入SQLite。

首次同步复制云端已保留的完整历史，后续按`updated_at`读取增量，并重叠回读1天以覆盖边界提交。历史日期价格修订只要云端更新时间改变，也会同步。使用服务端游标分批读取，避免全表装进内存；每批本地原子提交，全部传输成功才推进水位。网络或写盘失败保留已提交批次，但不推进成功水位，重跑幂等。

```bash
# 每天维护完成后执行同一命令，自动变成增量同步
.venv/bin/python scripts/sync_local_market.py --market all

# 首次仅复制几只自选股，快速开始
.venv/bin/python scripts/sync_local_market.py --market us --symbols AAPL,MSFT,NVDA
.venv/bin/python scripts/sync_local_market.py --market cn --symbols 600519,300750,000333

# 忽略水位重读云端当前历史，不删除本地更早历史
.venv/bin/python scripts/sync_local_market.py --market cn --full
```

不同市场、自选范围各自保存水位，新加股票不会继承旧列表水位而漏历史。默认路径变更不影响云端；同一本地库绑定一个云端数据库身份，换云端时需指定不同本机文件。当前仅支持已启用的PostgreSQL，不隐式回退到Supabase或在线行情。

云端异常OHLCV单独保存在`sync_issues`，不混入有效K线。其他股票继续同步；受影响股票暂不生成分析，避免无声丢K后计算。云端修正并更新时间后再次同步，会自动解除对应隔离。CLI返回码0为成功、1为传输/配置/本机写入失败、2为传输完成但有异常行隔离。异常隔离是显式处理完成，不属于网络中断。

本地库积累历史，不跟随云端保留策略删除旧行。首次只能得到云端已有历史；同步不会补出云端没有的年份，也不能修复云端本身的复权混用或已删除旧历史的调整问题。需要更长历史时，先扩展云端回填和保留策略。

## Actions负责的工作

- `CN Daily Market Data`：`wyckoff_funnel.yml`维护A股缓存，并写入沪深300基准。
- `US Daily Market Data`：`wyckoff_funnel_us.yml`维护S&P500名单及日线，并写入SPY基准。
- 新增的`refresh_market_benchmarks.py`仅用于Actions数据维护，不执行扫描或交易策略。基准使用独立键`INDEX:CN:000300`、`INDEX:US:SPY`，与同名个股分开。

两个工作流继续使用既有PG Secrets，必须与本机读取的数据库一致。工作流固定`PG_ENABLED=1`，启动前校验配置，缺失时直接失败，不再静默回退到Supabase。工作流修改提交到实际执行分支后才生效；本地改文件不代表GitHub已部署或任务已运行。基准尚未写入时，网页会明确提示先完成云端基准维护再同步，但仍分析可用个股。

## CSV 约定

UTF-8 编码、逗号分隔，最大5MB。必需列：`date,open,high,low,close,volume`；也支持 `日期,开盘,最高,最低,收盘,成交量`。一股一个文件时填写对应代码；多股文件必须增加 `symbol`／`代码` 列，A股代码保持六位（如 `000001`）。不接受分钟时间戳。

每股截至分析日需要至少100根日线；按日期排序，拒绝重复日期、非正价格、不合理高低关系、缺失或无穷 OHLCV、负成交量和最新零成交量。不修补异常K线。不把成交额反推为成交量。

CSV复权方式由上传者保证一致。本地库沿用云端`qfq`口径（美股由既有数据源自动调整），不在本机二次复权；观察卡价格是行情分析口径，不一定等于未复权的券商委托价格。

## 规则口径

版本为“日线研究 v1”。资料依据为 `research/martin_luk_final/Martin_Luk_回调买入法与其他交易方法_V2.0_最终整合版.md`（实际V4.1）；EMA9/21/50、先定位再触发、量价观察有资料支持。以下具体窗口和门槛是工程假设，尚未验证交易优势。

| 项目 | 定义 |
|---|---|
| 趋势 | EMA9＞21＞50，三线均高于5根前，收盘≥EMA21 |
| 强势回调 | 趋势成立；收盘低于此前5日最高收盘，或日低下移且收盘低于昨日高；日低距EMA9或21≤0.75 ATR且收盘守在线上；未延伸 |
| 收紧待突破 | 趋势成立；近3日均区间≤此前10日的70%，均量≤此前10日；未延伸 |
| 收紧突破 | 前一日满足收紧，今日收盘突破此前10日最高价，趋势成立且未延伸 |
| U&R | 日低跌破此前20日最低价、收盘高于该价；不强制趋势，弱趋势单独警示 |
| 延伸预警 | 收盘高于EMA21超过3 ATR |
| 结构偏弱 | 收盘低于EMA50；另提示EMA9下穿及此前20日低点失守 |
| ATR14 | 真实区间14日简单均值 |
| ADR20% | 20日平均 `(high/low−1)×100`，与ATR区分 |
| 相对强度 | 个股20日收益减基准同日期收益，单位百分点；不对齐则不计算，不作为硬筛选条件 |

界面可以调整支撑带宽、延伸距离和区间收缩比例。所有阈值随扫描条件保存于会话；结果导出包含规则版本及这三个参数。回调参考为本日高／近5日低；收紧参考为此前10日高／整理3日低；U&R参考为本日高／本日低。同股可有多标签，参考位优先U&R，再收紧，再回调。

所有滚动位只使用当时可知数据；分析截止日之后的行不参与任何指标。日线不能确定一根K内触发和止损的先后，不提供分钟入场、真实成交、仓位建议或收益回测。AVWAP自动锚点、事件催化及题材判断不在第一版范围内。

A股执行还需考虑T+1、涨跌停和停牌；美股仍有跳空和滑点。失效参考位不是保证成交的止损价，也不是最大亏损。
